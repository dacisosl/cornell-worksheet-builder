# 학습지 자동 편집 — 원래 원했던 방향

> 2026-08-20 기록. 다음에 이 기능을 다시 만들 때 출발점으로 쓴다.

## 원하는 것

교사가 **교과서를 캡처해서 붙여 놓은 미완성 학습지**를,
**깔끔하게 편집된 학습지**로 바꿔 주는 기능.

입력은 지금 빌더로 만드는 그 초안 그대로다 — 칸 안에 캡처 이미지가 여기저기 놓여 있고,
글씨체·크기가 제각각이고, 잘린 문장이 섞여 있는 상태.

출력은 둘 중 하나(또는 둘 다 고를 수 있게):

1. **하나의 자연스러운 문제 이미지로** — 여러 캡처 조각을 이어 붙여 한 문제처럼 보이게 정리.
   경계·여백·기울기·밝기가 튀지 않고 원래 한 장이었던 것처럼.
2. **원하는 칸에 텍스트로 다시 조판** — 캡처에서 글을 읽어 내(OCR) 지정한 칸에 다시 앉힌다.
   - **어절 단위로 줄바꿈** (한국어 문장이 낱말 중간에서 끊기지 않게)
   - 글씨체·글씨 크기·줄 간격을 문서 전체에서 통일
   - 문항 번호·보기(①②③)·수식·표가 원래 구조대로 유지

핵심은 **"내용 생성"이 아니라 "정리·편집"**이다. 새 문제를 지어내는 게 아니라,
이미 가진 자료를 보기 좋게 만드는 것.

## 왜 지난 시도가 빗나갔나

`worksheet-grab`(외부 오픈소스)을 붙여 봤다가 걷어냈다 (`ea66633`에서 삭제,
직전 상태는 `aa92798`에 보존).

빗나간 이유:

- 그 도구는 **활동지를 새로 설계·생성**하는 도구다. 교육과정 성취기준을 조회하고,
  활동 구조(아키타입)를 고르고, 본문을 AI가 새로 저작한다.
- 그래서 **내 초안의 캡처 이미지와 문장을 정리하는 일**은 아예 다루지 않는다.
  결과물이 초안과 따로 노는 별개의 문서가 나왔다.
- 성취기준·과목 같은 그 도구의 전제(교육과정 정렬)가 계속 걸림돌이 됐는데,
  정작 원하는 일(편집·조판)과는 상관이 없었다.

**교훈: 외부 소스는 "생성" 쪽이었고, 필요한 건 "편집" 쪽이다.**
다음에는 생성 도구를 가져오지 말고, 편집 파이프라인을 직접 만든다.

## 다음에 만들 때 생각해 볼 것

### 텍스트로 다시 조판하는 경로 (2번)

- **OCR**: 캡처에서 글자와 위치를 뽑아야 한다. 한국어 + 수식이 관건.
  - 브라우저에서 vision 모델 API에 이미지를 직접 보내는 방법 (지금 구조에 가장 가깝다)
  - 문항 번호·보기 기호·표를 구조로 인식해야 단순 텍스트 덩어리가 안 된다
- **어절 단위 줄바꿈**: CSS `word-break: keep-all` + `overflow-wrap: break-word` 가
  한국어 어절 보존의 기본. 여기에 칸 폭에 맞춘 글씨 크기 자동 조절을 얹는다.
- **조판 통일**: 문서 전체에 쓰는 글씨체·크기·줄 간격 프리셋을 정해 두고,
  칸 종류(문제/풀이/개념)별로 적용.
- 원본 캡처는 지우지 말고 남겨 둔다 — OCR이 틀렸을 때 교사가 대조·복구할 수 있게.

### 이미지를 한 장으로 합치는 경로 (1번)

- 캔버스에서 조각들을 이어 붙이고 여백·정렬을 맞추는 건 API 없이도 가능하다.
- 밝기·기울기 보정, 배경 흰색 정규화 정도면 "한 장처럼" 보이는 데 대부분 해결된다.
- 이미 있는 것들을 재료로 쓸 수 있다: `imageProcessing.ts`(언샤프 마스크),
  `images.ts`의 자르기·겹침 정리·그룹 묶기.

### 공통

- **미리보기 → 사람이 확인 → 적용** 순서. 편집 결과를 바로 덮어쓰지 않는다.
- 실패해도 초안은 그대로 남아야 한다.
- AI를 쓴다면 키는 이 브라우저에만 두는 방식(지난 구현의 `aiClient.ts` 참고 —
  OpenRouter/Gemini 양쪽 지원, `aa92798`에 있다).
